# 来电知人 · V1 界面设计

设计日期：2026-11-07。品牌名暂定“来电知人”，应用标识暂定 `com.zuozishi.callhelper`。

## 产品边界

**保留手机原有来电显示页面，本应用只叠加独立的人员信息悬浮窗。** 不替换拨号器，不实现接听或挂断按钮，不取得默认拨号器角色。设计图中蓝灰色电话背景及接听、挂断控件属于原有电话应用的背景示意；只有白色人员身份卡片属于本应用。

来电识别角色与默认拨号器角色是两项不同能力。具体授权方式以 Android 实施验证为准。

## 视觉规范

### 文案精简规则

移除不必要的文本；能用清晰图标表示的操作使用图标；标题和控件含义明确时不再追加解释性小字。保留姓名、岗位、单位等核心信息、更新时间、必要错误原因和简短权限用途。纯图标按钮提供无障碍名称及悬停提示。

本次调整移除页面宣传语、重复状态和浮窗操作说明；导航、主题选择、同步、预览与授权入口采用图标；同步失败预览入口移至设计板标题旁，不放入产品界面。人员信息字段保持完整。

设计尺寸 390 × 844 逻辑像素，外边框只用于设计展示，实际布局以设备可用空间与系统 Insets 为准。字体首选系统 MiSans，未安装时回退系统中文字体，设计图使用本机可用字体。字号、圆角均为初始设计值，不宣称是 Miuix 官方默认值。

| 项目 | 设计值 |
| --- | --- |
| 页面背景 | `#F5F5F5` |
| 卡片 | `#FFFFFF` |
| 主强调色 | `#3482FF` |
| 主要文字 | `#191B20` |
| 次要文字 | `#858991`；正式实现需验证不同背景下的可读性 |
| 正向状态 | `#22A974`，同时配合文字 |
| 页面左右留白 | 21dp，按设备宽度自适应 |
| 大标题 | 31sp / 600–650 |
| 人员姓名 | 28sp / 600；浮窗最强信息层级 |
| 岗位、单位 | 11–14sp；大字号模式随系统或设置放大 |
| 卡片圆角 | 24dp；浮窗 28dp；按钮 16dp |
| 触控区域 | 实施时所有可操作控件不少于 48dp |

以 Miuix 的原生组件表现为优先，HTML 仅用于设计评审，不将 CSS 像素硬搬为 Android 尺寸。模糊、透明度与阴影只作为可选装饰，需有不透明背景回退；姓名与岗位始终可读。

## Miuix 组件映射

对照官方组件目录规划；具体 API 与依赖版本在实施阶段锁定，仓库仍标记为实验性 API。

| 设计部位 | 原生实现方向 |
| --- | --- |
| 页面与大标题 | Scaffold、TopAppBar |
| 首页 / 人员卡片 | Card、BasicComponent、Text |
| 底部导航 | NavigationBar |
| 搜索与筛选 | SearchBar、TabRow 或受控按钮组 |
| 同步操作 | Button、ProgressIndicator、Snackbar |
| 外观 / 显示设置 | Switch、Slider、基础设置行 |
| 图标 | miuix-icons；缺失图标使用统一线性图标 |
| 来电浮窗 | WindowManager 承载 Compose 内容，内部复用 MiuixTheme / Card / Text |

Miuix 本身是 UI 库，不提供电话识别或系统级浮窗服务。系统授权页由 Android / HyperOS 展示，本应用只做进入前说明与状态回读。

## 独立浮窗规范

1. 来电时在原电话页面上叠加卡片，按“姓名 → 岗位 → 单位 → 部门”展示；未加载数据时不要伪装已匹配。
2. 默认水平留白约 16dp、宽度为屏宽减 32dp；高度随内容自适应，长单位支持换行。优先放在屏幕中部空白区域，避开号码、原生接听 / 挂断及系统导航。实际位置随原电话应用布局调整并在真机确认。
3. 长按拖动，上下移动到可用区域；关闭按钮只隐藏本次浮窗，持续来电不反复弹出。同一来电仅一个浮窗实例。
4. 不抢系统电话页面焦点，不铺设全屏透明遮罩；卡片外区域由原界面正常操作。
5. 未匹配显示“未找到人员信息”；号码未提供时明确说明；多个人员精确命中时展示“匹配到多位人员”，展开查看，禁止猜选身份。
6. 接听后默认短暂显示再收起；通话结束后立即移除。具体生命周期监听方案在实施时验证。
7. 深色遵循系统外观，也可单独配置。锁屏默认隐藏人员详情；不将锁屏展示视为已实现能力。

## 同步及其他状态

| 场景 | 呈现与操作 |
| --- | --- |
| 未授权 | 首页“待完成设置”，进入逐项引导 |
| 未同步 | 人员库空态，主操作“连接数据源并同步” |
| 同步中 | 显示下载 / 校验 / 导入阶段，禁用重复提交，已有库继续查号 |
| 成功 | 更新数量与时间，切换到新库 |
| 网络 / 解密 / CSV 校验失败 | 明确失败原因、重试入口、上次可用版本；失败数据不覆盖原库 |
| 无可用人员库且同步失败 | 提示“暂无可用人员库”，不展示“仍可识别” |
| 号码无匹配 | 浮窗保留号码与未匹配说明，不虚构姓名 |
| 名称 / 岗位 / 单位超长 | 优先换行；详情入口查看全文，不让文字盖住关闭按钮 |
| 暂停识别 | 首页显示“已暂停”，保留人员库的手动查询 |

## 演示范围和验收

交互稿可演示搜索、单位筛选、空结果、浮窗关闭与恢复、外观、字号、部门开关、暂停及同步失败 / 重试。授权入口只解释后续原生跳转；没有调用真实系统权限、电话服务或后端。同步动画为本地计时模拟。

导出与交互检查结果见 `validation.json`。本阶段交付设计资产，不包含 Android 编译、真实加密数据处理、系统电话集成或真机测试。设备验收需覆盖不同电话 App、HyperOS 版本、横竖屏、双卡、锁屏、后台、系统字体缩放与重复号码场景。
