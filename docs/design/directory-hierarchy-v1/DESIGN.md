# 人员库组织层级设计 V1

2026-11-08。此轮仅设计，不修改 Android 实现。延续现有浅色背景、白色卡片、蓝色强调色及纯图标底部导航。

## 浏览方式

- 默认列出顶级单位，不展开全部人员。点击文件夹进入子组织；当前层级先列子组织，再列直属人员。
- 文件夹右侧人数表示该组织子树的人员总数；直属人员单独计数，避免与子部门人员混淆。
- 顶部面包屑可回跳。层级过深时保留最近节点，正式实现应支持横向滚动访问完整路径。
- 返回按钮与系统返回均先回上一级；根级再执行应用原有返回行为。正式实现需保存每层滚动位置。
- 人员行保留姓名、岗位、号码；点击查看完整组织路径与人员详情。
- 搜索始终覆盖全库，结果附完整组织路径；清空关键词恢复原目录。空结果显示简短状态。
- 缺失组织路径的人员归入“未归属组织”；组织内无直属人员和子组织时显示空态。
- 图标按钮保留无障碍名称；不添加重复说明性小字。

## 数据与性能实施方向

现有 Personnel 包含 TopOrgName 和 FullOrgName，可以建立组织索引。组织节点应以完整路径作为键，避免不同单位的同名部门合并。路径分隔规则需依据实际导入格式确定，空段与顶级单位重复应规范化。

导入后在后台一次构建组织树、直属人员索引和子树计数。浏览仅读取当前节点，原生列表按当前层级惰性渲染；组织统计不得在列表重组时反复扫描全库。搜索继续后台执行并取消过期任务，结果分批呈现。头像按需加载，避免解码阻塞主线程。

这些是待实施方案，尚未定位所有卡顿来源，也未完成性能验收。后续需用真实库规模验证进入页面、逐层切换、快速滚动、连续搜索和返回位置恢复。

## 文件

- overview.png：三屏总览，使用虚构示例数据和示意规模。
- units.png、departments.png、people.png：单屏设计。
- index.html：离线交互原型，覆盖单位、研发中心、移动开发组、搜索及详情；其他目录只提供空态演示，非完整人员库。
- validation.json：原型检查结果，不代表 Android 或真机验收。
- 导出脚本：scripts/render_directory_hierarchy.py。

HTML 的玻璃导航为视觉示意。正式实现延用已有原生组件；返回位置恢复、完整路径横向滚动和大库加载仍待开发。
