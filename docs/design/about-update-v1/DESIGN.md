## 界面与交互

沿用现有 Miuix 风格：背景 `#F5F5F5`、主色 `#3482FF`、白色圆角卡片；深色使用现有 `#101216` / `#252A34`。设计基准 390 × 844。底部保留首页、人员库、数据同步、设置，新增信息圆圈图标作为“关于”；五个入口均不增加可见文字，每项保留无障碍名称和选中语义。原生实现延续 LiquidBottomTabs；HTML 中玻璃效果仅为视觉示意。

关于页按应用标识与版本、检查更新、仓库及作者、更新记录排列。仓库链接指向 `https://github.com/zuozishi/CallHelper`，作者链接指向 `https://github.com/zuozishi`。长链接显示仓库名称而非完整 URL。必要操作与状态保留文字，不添加宣传语、重复副标题或镜像开关。

| 场景 | 设计行为 |
| --- | --- |
| 应用冷启动 | 后台异步检查一次，不显示加载、Toast 或阻塞页面；从系统设置返回、旋转屏幕不重复检查 |
| 启动检查失败 | 镜像与官方均失败后静默结束，不显示提示、警告、错误卡片或失败标记 |
| 启动检查无新版 | 静默结束 |
| 发现新版 | 前台展示更新底部弹层：版本、包大小、更新说明、下载更新与稍后；同次启动关闭后不重复打扰 |
| 手动检查中 | 原按钮显示“正在检查”与进度指示，禁用重复点击 |
| 手动检查无新版 | 卡片内显示“已是最新版本”，不弹额外对话框 |
| 手动检查失败 | 卡片内显示“无法连接，请重试”；检查按钮恢复可用 |
| 下载中 | 显示百分比、已下载/总大小，支持收起、取消；大小未知时用不定进度与已下载大小，不编造百分比 |
| 收起下载 | 继续下载；关于页更新卡片变为下载进度，点击恢复弹层 |
| 下载失败 | 镜像失败自动尝试官方；均失败则下载弹层显示“下载失败，请重试”，主按钮为“重试下载”，保留关闭操作 |
| 下载并校验完成 | 应用在前台且已有安装权限时立即调用系统安装器；不再要求点击一次“立即安装” |
| 尚无安装权限 | 展示图中简短用途说明；前往系统设置，授权返回后自动调用系统安装器 |
| 用户拒绝授权或取消安装 | 保留已校验安装包；关于页显示“安装更新”以便再次调用，不强制反复跳转 |
| 下载完成时应用在后台 | 保存已校验安装包，返回前台后自动继续安装流程；后台通知入口按系统权限和约束实现，不强行弹起系统界面 |
| 安装成功后启动 | 按当前实际安装版本显示；清理旧安装包 |

图中的授权页是本应用的前置说明，不是仿制系统设置。系统安装器界面与最终安装确认由 Android / HyperOS 提供。“自动触发安装”指自动调起系统安装器，普通应用升级仍受系统授权与确认约束。

更新记录页展示 Release 版本、发布日期和发布说明，当前版本带标签。优先展示已缓存历史，后台刷新失败保留可读内容；无缓存且加载失败时显示“暂时无法获取更新记录”与重试。没有历史记录时显示“暂无更新记录”。长说明可滚动，解析为受控原生文本，链接单独处理，不执行远端 HTML。当前版本可以预置公开更新说明作为离线内容；不能将人员库数据混入缓存。

## 后续实现约定

1. Release 元信息与 APK 均采用镜像优先、官方回退；不把镜像切换表现为错误提示。候选元信息地址为 `https://gh-proxy.com/https://api.github.com/repos/zuozishi/CallHelper/releases/latest`，官方为 `https://api.github.com/repos/zuozishi/CallHelper/releases/latest`；历史列表使用 `/releases`。APK 取 Release asset 的 `browser_download_url`，镜像地址用 `https://gh-proxy.com/` 加原始完整 URL。按需过滤 draft / prerelease，只提示高于已安装版本的稳定版本。
2. 分别处理元信息和下载回退：超时、连接错误、非预期 HTTP 响应、HTML 冒充 JSON/APK 或解析失败都应触发后备路线。下载回退时清理未完成临时文件，从官方重新下载；除非已验证 Range/ETag，否则不混合来源断点内容。设置有限超时，避免无休止重试。
3. 下载前核对 asset 类型及设备兼容性。完成后校验文件完整性、包名、可升级版本和签名一致性；校验失败不交给安装器。来源校验和可辅助完整性检查，不能代替应用签名验证。没有兼容 APK 时明确说明并提供 Release 页面入口。
4. 单一检查/下载任务去重，页面切换不重复发起。启动检查与人员库提醒分别管理，避免叠加多个弹层；主动授权和现有业务对话框结束后再提示新版本。
5. 实现阶段加入安装权限、私有下载目录、FileProvider 及临时只读 URI 授权。检查返回前台后的权限，避免循环打开设置；调用失败或安装器不可用时保留“安装更新”重试入口。
6. 预期实现顺序为 About 页面与状态模型、Release 双路查询、APK 双路下载与校验、系统安装器与授权恢复。需要验证真实镜像 API、官方回退及设备安装流程后才能宣称功能完成。

## 设计验证与限制

使用 `python scripts/render_update_design.py` 生成 HTML 和 PNG。脚本检查启动网络失败无状态提示、手动失败反馈、最新版本反馈、新版弹层关闭以及页面水平溢出。PNG 另行目视检查。原型不进行联网检查、真实下载、系统授权或安装；导航仅展示拟定布局，历史按钮可定位到更新记录设计屏。未进行 Android 构建或真机测试。
